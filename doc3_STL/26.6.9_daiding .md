##  1.智能指针补充：

```
主要有三种智能指针(位于<memory>头文件中)
1.std::unique_ptr<T>(独占所有权)
    不能被复制,只能被移动(std::move)
    适用于独占资源管理(如文件、网络连接)
    用std::make_unique<T>(args...)创建(C++14+)

2.std::share_ptr<T> (共享所有权)
    采用引用计数多个shared_ptr可共享同一对象最后一个销毁时释放资源
    存在循环引用风险可配合std::weak_ptr解决
    用std::make_shared<T>(args...)创建减少内存分配开销

3.std_weak_ptr<T>(弱引用)
    依赖shared_ptr,不会增加引用计数
    用于解决shared_ptr循环引用问题
    可通过lock()获取shared_ptr,判断对象是否仍然有效

```


std::shared_ptr<T>原理是什么? 请手动实现

```
原理:
每个shared_ptr实例指向同一对象的其他shared_ptr实例共享一个计数器
当创建shared_ptr或拷贝现有的shared_ptr时,计数器增加
当shared_ptr被销毁(例如通过析构函数)或重置(通过reset方法)时,计数器减少
当计数器为0时,对象被自动删除，通常通过调用delete操作符

这种机制确保了对象在最后一个shared_ptr销毁时被释放,防止了内存泄漏
适合多线程或复杂数据结构中需要共享对象的场景


```

手写shared_ptr 示例：

```c++
#include<iostream>
using namespace std;

//辅助类：用于管理共享指针的引用计数
template<typename T>
class sharedCount
{
private:
    T* ptr;  //指向管理的对象
    int count; //共享指针的引用计数

    //禁止拷贝构造和拷贝赋值避免多次管理同一个资源
    sharedCount(const sharedCount&) = delete;
    sharedCount& operator = (const sharedCount&) = delete;
public:
    sharedCount(T *p) : ptr(p), count(1) {}
    ~sharedCount() {delete ptr;}  //析构函数

    //增加引用计数
    void increment(){ count++; }
    //减少引用计数
    void decrement()
    {
        if(--count == 0)
            delete this;      //当count为0时 把内存释放掉   delete this就是去直接调用析构函数 ~sharedCount() {delete ptr}
            
    }     

    T* get() const {        //get()的内部语义:获取内部裸指针
        return ptr;
    }


};

template<typename T>
class shared_ptr
{
private:
    T* ptr; //指向管理的对象      ------>✅️ 指向真正的数据
    sharedCount<T>* countPtr;     //指向引用计数对象
    //管理智能指针引用计数类对象      countPtr是一个指针指向sharedCount<T>类型的对象
    //注意： shareCount只是一个模板名字不是一个真正能直接创建对象的类型 shareCount<T>才是具体类型  类比 vector<int> v;  -->这样是错的❌️vector v;❌️

public:
    shared_ptr(T* p = nullptr) : ptr(p)
    {
        if(p)
        {
            countptr = new sharedCount<T>(p);
        }
        else
        {
            p = nullptr;
        }
    }

    //拷贝构造函数,他只是共享所有权并不是创建新的内存对象，只是引用计数增加而已
    shared_ptr(const shared_ptr& other) : ptr(other.ptr), countPtr(other.countPtr)
    {
        if(countPtr)
        {
            countPtr->increment();
        }
    }

    //移动构造函数
    shared_ptr(shared_ptr&& other) : ptr(other.ptr), countPtr(other.countPtr)
    {
        other.ptr = nullptr;   //虽然 ptr 是 private，但是同一个类的成员函数可以访问另一个同类型对象的 private 成员。
        other.countPtr = nullptr;      //因为是移动，原本的就要清空
    }

    ~shared_ptr()
    {
        if(countPtr)
        {
            countPtr->decrement();
        }
    }

    //重载一个箭头运算符
    T* operator-> () const
    {
        return ptr;
    }
    //智能指针如何访问到对象地址，对智能指针进行解引用就是访问的原对象
    T& operator* () const      //const的作用：这个函数不会修改智能指针对象本身的成员变量
    {
        return *ptr;           //这里：return *ptr;   返回的是 ptr 指向的对象本身
    }

    //reset
    void reset(T* p = nullptr)
    {
        if(p!=ptr)
        {
            if(countPtr)
            {
                countPtr->decrement();
            }
        }
    }

    ptr = p;
    if(p)
    {
        countPtr = new shared_ptr<T>(p);
    }
    else
    {
        countPtr = nullptr;
    }
};

int main()
{
    shared_ptr<int> ptr1(new int(10));  //还有另外一种写法：std::make_shared<>....
    cout<<"ptr1:"<<*ptr1<<endl;
    cout<<"ptr2:"<<*ptr2<<endl;

    ptr1.reset();
    cout<<"ptr2:"<<*ptr2<<endl;

    shared_ptr<int> ptr3 = std::move(ptr2);
    cout<<"ptr3:"<<*ptr3<<endl;
    
}


```

std::make_shared<T>(args...)相比std::shared_ptr<T>(new T(args...))有什么好处:

1.避免额外的内存分配
```
std::make_shared会在一次内存分配中同时分配对象本体和引用计数
而std::shared_ptr<T>(new T(args...))需要分配两(一次给T，一次给shared_ptr的控制块)
这不仅减少molloc/free的开销,还能提高缓存命中率
```
2.减少异常安全问题
```
std::shared_ptr<T>(new T(args...))是两个独立操作,new T(args...)可能会抛出异常,而shared_ptr还未成功构造,导致内存泄漏
这种情况担心中途抛异常这样导致函数还未构造完成就失败了 导致内存泄漏
std::make_shared<T>(args...) 进行的是原子操作不存在这个问题
这里说它更加原子指的是：它把“申请内存 + 构造对象 + 创建引用计数控制块 + 交给 shared_ptr 管理”封装成一个整体过程，避免中间裸指针暴露，更安全。
make_shared 不会让裸指针暴露在外面
```
3.更高效的引用计数管理
```
由于make_shared在一个存储块中存储对象和引用计数、指针访问是可以减少额外的访问缓存提高运行效率
std::shared_ptr<T>(new T(args...))由于分开分配对象和控制块会导致额外的指针间接访问
```
4.代码更简洁
